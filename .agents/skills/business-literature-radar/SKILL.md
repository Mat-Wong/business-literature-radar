# 商科文献雷达 · Codex 工作流

Work from the extracted product/repository root (the folder containing `search_papers.py`, `search_v2.py`, and `agent_bridge.py`). This skill uses Codex's native model for reasoning and translation; the local engine retrieves public metadata. No LLM API key is needed. On Windows, commands below can use `BusinessLiteratureRadar.exe --engine search`, `--engine v2`, or `--engine bridge` in place of `python search_papers.py`, `python search_v2.py`, or `python agent_bridge.py` respectively.

## Search and refine

1. Confirm the research question, year range, business-school disciplines, desired sources, result count, and whether every displayed title/available abstract needs a Chinese translation. Use the user's choices; otherwise state sensible defaults. Inspect `--help` for the live engine options.
2. Generate a draft plan with `python search_papers.py "<question>" --years <start-end> --disciplines <comma-separated> --sources <comma-separated> --api-provider rules --llm-backend rules --plan-only --plan-output <output/plan.json>`. Treat rules-mode terms as a limited lexical scaffold, not as research advice or a complete translation. Use your own model to replace every topic-dependent field with question-specific values (`english_query`, `expanded_queries`, `method_terms`, `data_terms`, `target_terms`, `must_have_terms`, `nice_to_have_terms`, `exclude_terms`, `arxiv_queries` if arXiv is selected, `summary`, `folder_title`). Empty fields are acceptable when the question provides no defensible terms for that category. Keep `selected_disciplines` aligned with the chosen flags. Save the edited plan and show its main scope to the user before retrieval when their choices are ambiguous.
3. Run round one with the same question and filters plus `--limit <count> --plan-file <output/plan.json> --output-dir output --create-run-folder --progress --api-provider rules --llm-backend rules --no-opencode-fallback`. Do not pass `--translate-abstracts`: Codex, not the engine's API backend, will perform the translations. Capture the exact JSON path printed by the engine; do not guess the timestamped filename.
4. Read the result JSON (`results`, `issues`, `plan`) and screen titles/abstracts against the question. Write a feedback JSON containing `{"feedback":[{"title":"<exact original title>","doi":"<DOI or empty>","state":"relevant|irrelevant|uncertain"}]}`. Be explicit that these are agent-proposed judgments unless the user supplied them. If there is at least one relevant or irrelevant item, run `python search_v2.py --report-json <round-one.json> --feedback-json <feedback.json> --api-provider rules --llm-backend rules --no-opencode-fallback`; capture its exact final JSON path. Include the second-round and citation-expansion audit in the final assessment. If round one is empty or the user asked for one round only, use its report and explain why deep search was skipped.

## Translate and report

When translation was requested, run `python agent_bridge.py prepare --report-json <final.json>`. For every `batch_*.input.json` it creates, translate each paper's `source_title` and *available* `source_abstract` using your native model. Write the matching `batch_NNN.translated.json` beside it, shaped as `{"translations":[{"index":1,"source_title":"<exact unchanged original title>","title_zh":"...","abstract_zh":"..."}]}`. Include every index, preserve technical terms and findings, and use `abstract_zh: ""` when the source abstract is empty; never supply an invented abstract. Process batches incrementally if context is tight. Then run `python agent_bridge.py apply --report-json <final.json> --agent-name codex`. It rejects missing or mismatched translations and writes separate `-agent` JSON, HTML, Markdown, and CSV files; finish only after it reports full coverage. The original report remains available for audit.

Create a concise bilingual research memo beside the final report: search scope and source issues; a themed shortlist with exact DOI or source links; what each abstract actually supports; methods/data/gaps worth checking; and the second-round changes. Distinguish metadata/abstract evidence from unverified full-text claims. Link the bilingual HTML report and memo in the final response. If a source failed or translation cannot be completed, report the remaining count and paths rather than claiming completion. This workflow never needs a personal API key or a Claude/Codex subscription bridge inside the web app.
